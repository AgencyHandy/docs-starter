تتيح لك واجهة AgencyHandy API أتمتة إنشاء العملاء المحتملين وإدارة العملاء وتحديثات الطلبات وغير ذلك من أي نظام خارجي أو برنامج نصي. تتم مصادقة كل طلب باستخدام مفتاح API الذي تنشئه من إعدادات مساحة العمل. يرشدك هذا الدليل خلال إنشاء المفتاح وإجراء أول استدعاء لـ API.

<Note>
  يجب أن تكون **مشرفًا عامًا (SuperAdmin)** أو **مشرفًا (Admin)** في مساحة عمل AgencyHandy لإنشاء مفتاح API.
</Note>

## عنوان URL الأساسي

جميع طلبات API ترسَل إلى:

```
https://api.agencyhandy.com/api/v1
```

استبدل `{{URL}}` بعنوان URL الأساسي هذا في جميع أمثلة الطلبات عبر وثائق API.

## الخطوة 1: إنشاء مفتاح API

<Steps>
  <Step title="فتح تكوين مساحة العمل">
    انتقل إلى إعدادات مساحة العمل على:

    ```
    {{workspaceUrl}}/workspace-config?tab=api-key
    ```

    يفتح هذا تبويب **مفتاح API** داخل تكوين مساحة العمل.
  </Step>

  <Step title="إنشاء مفتاح API ونسخه">
    انقر على **إنشاء** (أو **إعادة الإنشاء** إذا كان مفتاح موجودًا بالفعل). انسخ مفتاح API واحتفظ به بأمان — عامله ككلمة مرور. لن تعرضه AgencyHandy مرة أخرى بعد مغادرة الصفحة.
  </Step>
</Steps>

<Warning>
  يؤدي إعادة إنشاء مفتاح API إلى إبطال المفتاح السابق فورًا. ستتوقف أي تكاملات موجودة تستخدم المفتاح القديم حتى تقوم بتحديثها بالمفتاح الجديد.
</Warning>

## الخطوة 2: أجرِ أول استدعاء

أرسل مفتاح API في الترويسة `x-api-key`. ينتمي المفتاح إلى مساحة عمل واحدة، لذا تقرأ API مساحة العمل من المفتاح ولا تحتاج إلى إرسال معرّف الشركة. يعيد هذا الاستدعاء معرّف مساحة عمل المفتاح ومساحات العمل المرتبطة به:

### النقطة النهائية

```
GET {{URL}}/accounts/companies
```

### الترويسات

| الترويسة | القيمة |
|---|---|
| `x-api-key` | مفتاح API الخاص بك |

### مثال على الطلب

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/accounts/companies" \
  --header "x-api-key: <YOUR_API_KEY>"
```

### مثال على الاستجابة

```json
{
  "message": "Companies accosiated with API token.",
  "companyId": "6525994184e9ddd79853450e",
  "companies": [
    {
      "_id": "6525994184e9ddd79853450e",
      "name": "onethread123",
      "logo": "",
      "extraSmallLogo": "",
      "largeLogo": ""
    }
  ]
}
```

`companyId` هو مساحة العمل التي ينتمي إليها مفتاح API الخاص بك. يسرد `companies` أيضًا أي مساحات عمل رئيسية أو فرعية مرتبطة به؛ لا يعمل مفتاح API إلا لمساحة العمل الخاصة به، لذا أنشئ مفتاحًا منفصلًا في كل مساحة عمل تريد أتمتتها.

## ملخص المصادقة

يحتاج كل طلب موثّق إلى مفتاح API الخاص بك فقط:

```
x-api-key: <YOUR_API_KEY>
```

- **عنوان URL الأساسي:** يبدأ كل مسار بـ `https://api.agencyhandy.com/api/v1`. يؤدي استدعاء `https://api.agencyhandy.com/accounts/companies` بدون `/api/v1` إلى إرجاع `404 API not found`.
- **ترويسة `companyid` (اختيارية):** ترسل الأمثلة الأقدم `companyid: <YOUR_COMPANY_ID>`. يمكنك الاستمرار في إرسالها، لكن يجب أن تكون معرّف مساحة العمل الخاصة بالمفتاح نفسه. يُرفض أي معرّف مختلف مع `403 PermissionError`.
- يعمل **`Authorization: Bearer <YOUR_API_KEY>`** أيضًا إذا كانت أداتك لا تستطيع إرسال سوى رمز bearer. أرسل المفتاح في ترويسة واحدة فقط، وليس في كلتيهما.
- يعني **`401 Invalid API key (jwt malformed)`** أن القيمة ليست المفتاح الكامل: انسخ المفتاح بالكامل عند إنشائه (تعرض قائمة مفاتيح API آخر خمسة أحرف منه فقط). ويعني **`401 Invalid api token`** أن المفتاح قد حُذف.
- يُنفَّذ كل استدعاء بصلاحيات العضو الذي أنشأ المفتاح.

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/members" \
  --header "x-api-key: <YOUR_API_KEY>"
```

بمفتاح API الخاص بك، أصبحت جاهزًا لاستخدام بقية واجهة AgencyHandy API. تابع إلى أحد أدلة نقاط النهاية أدناه.
