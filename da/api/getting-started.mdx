AgencyHandy API'et lader dig automatisere oprettelse af leads, kundestyring, ordreopdateringer og meget mere fra ethvert eksternt system eller script. Hver anmodning godkendes med en API-nøgle, som du genererer i dit workspaces indstillinger. Denne guide fører dig gennem generering af din nøgle og dit første API-kald.

<Note>
  Du skal være **SuperAdmin** eller **Admin** på dit AgencyHandy-workspace for at generere en API-nøgle.
</Note>

## Basis-URL

Alle API-anmodninger foretages til:

```
https://api.agencyhandy.com/api/v1
```

Erstat `{{URL}}` med denne basis-URL i alle eksempelanmodninger i hele API-dokumentationen.

## Trin 1: Generer en API-nøgle

<Steps>
  <Step title="Åbn workspace-konfiguration">
    Naviger til dine workspace-indstillinger på:

    ```
    {{workspaceUrl}}/workspace-config?tab=api-key
    ```

    Dette åbner fanen **API Key** inde i Workspace Configuration.
  </Step>

  <Step title="Generer og kopiér din API-nøgle">
    Klik på **Generate** (eller **Regenerate**, hvis der allerede eksisterer en nøgle). Kopiér API-nøglen og opbevar den sikkert — behandl den som en adgangskode. AgencyHandy vil ikke vise den igen, når du forlader siden.
  </Step>
</Steps>

<Warning>
  Regenerering af din API-nøgle ugyldiggør straks den tidligere nøgle. Alle eksisterende integrationer, der bruger den gamle nøgle, holder op med at virke, indtil du opdaterer dem med den nye nøgle.
</Warning>

## Trin 2: Foretag dit første kald

Send din API-nøgle i `x-api-key`-headeren. Nøglen tilhører ét workspace, så API'et aflæser workspacet fra nøglen, og du behøver ikke sende et virksomheds-ID. Dette kald returnerer nøglens workspace-ID og de workspaces, der er knyttet til det:

### Endpoint

```
GET {{URL}}/accounts/companies
```

### Headers

| Header | Værdi |
|---|---|
| `x-api-key` | Din API-nøgle |

### Eksempelanmodning

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/accounts/companies" \
  --header "x-api-key: <YOUR_API_KEY>"
```

### Eksempelsvar

```json
{
  "message": "Companies accosiated with API token.",
  "companyId": "6525994184e9ddd79853450e",
  "companies": [
    {
      "_id": "6525994184e9ddd79853450e",
      "name": "onethread123",
      "logo": "",
      "extraSmallLogo": "",
      "largeLogo": ""
    }
  ]
}
```

`companyId` er det workspace, din API-nøgle tilhører. `companies` viser også overordnede eller underordnede workspaces, der er knyttet til det; en API-nøgle virker kun for sit eget workspace, så opret en separat nøgle i hvert workspace, du vil automatisere.

## Oversigt over godkendelse

Hver godkendt anmodning kræver kun din API-nøgle:

```
x-api-key: <YOUR_API_KEY>
```

- **Basis-URL:** hver sti starter med `https://api.agencyhandy.com/api/v1`. Et kald til `https://api.agencyhandy.com/accounts/companies` uden `/api/v1` returnerer `404 API not found`.
- **`companyid`-header (valgfri):** ældre eksempler sender `companyid: <YOUR_COMPANY_ID>`. Du kan fortsætte med at sende den, men den skal være nøglens eget workspace-ID. Et andet ID afvises med `403 PermissionError`.
- **`Authorization: Bearer <YOUR_API_KEY>`** virker også, hvis dit værktøj kun kan sende et bearer-token. Send nøglen i kun én header, ikke begge.
- **`401 Invalid API key (jwt malformed)`** betyder, at værdien ikke er hele nøglen: kopiér hele nøglen, når du genererer den (listen over API-nøgler viser kun de sidste fem tegn). **`401 Invalid api token`** betyder, at nøglen er slettet.
- Hvert kald køres med rettighederne for det medlem, der oprettede nøglen.

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/members" \
  --header "x-api-key: <YOUR_API_KEY>"
```

Med din API-nøgle er du klar til at bruge resten af AgencyHandy API'et. Fortsæt til en af endpoint-guiderne nedenfor.
