AgencyHandy API leidžia automatizuoti potencialių klientų kūrimą, klientų valdymą, užsakymų atnaujinimus ir kt. iš bet kokios išorinės sistemos ar scenarijaus. Kiekviena užklausa autentifikuojama API raktu, kurį sugeneruojate savo darbo srities nustatymuose. Šis vadovas padės sugeneruoti raktą ir atlikti pirmąjį API iškvietimą.

<Note>
  Norint sugeneruoti API raktą, jūsų AgencyHandy darbo srityje turite turėti **SuperAdmin** arba **Admin** vaidmenį.
</Note>

## Bazinis URL

Visos API užklausos siunčiamos į:

```
https://api.agencyhandy.com/api/v1
```

Visuose pavyzdiniuose užklausose visoje API dokumentacijoje pakeiskite `{{URL}}` šiuo baziniu URL.

## 1 žingsnis: Sugeneruokite API raktą

<Steps>
  <Step title="Atidarykite darbo srities konfigūraciją">
    Eikite į savo darbo srities nustatymus:

    ```
    {{workspaceUrl}}/workspace-config?tab=api-key
    ```

    Tai atidaro skirtuką **API Key** darbo srities konfigūracijoje.
  </Step>

  <Step title="Sugeneruokite ir nukopijuokite API raktą">
    Spustelėkite **Generate** (arba **Regenerate**, jei raktas jau egzistuoja). Nukopijuokite API raktą ir saugiai jį išsaugokite — elkitės su juo kaip su slaptažodžiu. AgencyHandy jo neberodys, kai išeisite iš puslapio.
  </Step>
</Steps>

<Warning>
  Regeneravus API raktą, ankstesnis raktas iš karto panaikinamas. Visos esamos integracijos, naudojančios seną raktą, nustos veikti, kol neatnaujinsite jų nauju raktu.
</Warning>

## 2 veiksmas: atlikite pirmąjį iškvietimą

Siųskite savo API raktą antraštėje `x-api-key`. Raktas priklauso vienai darbo sričiai, todėl API nuskaito darbo sritį iš rakto ir jums nereikia siųsti įmonės ID. Šis iškvietimas grąžina rakto darbo srities ID ir su ja susietas darbo sritis:

### Galinis taškas

```
GET {{URL}}/accounts/companies
```

### Antraštės

| Antraštė | Reikšmė |
|---|---|
| `x-api-key` | Jūsų API raktas |

### Pavyzdinė užklausa

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/accounts/companies" \
  --header "x-api-key: <YOUR_API_KEY>"
```

### Pavyzdinis atsakymas

```json
{
  "message": "Companies accosiated with API token.",
  "companyId": "6525994184e9ddd79853450e",
  "companies": [
    {
      "_id": "6525994184e9ddd79853450e",
      "name": "onethread123",
      "logo": "",
      "extraSmallLogo": "",
      "largeLogo": ""
    }
  ]
}
```

`companyId` yra darbo sritis, kuriai priklauso jūsų API raktas. `companies` taip pat išvardija susietas pagrindines ar antrines darbo sritis; API raktas veikia tik savo darbo srityje, todėl sukurkite atskirą raktą kiekvienoje darbo srityje, kurią norite automatizuoti.

## Autentifikavimo santrauka

Kiekvienai autentifikuotai užklausai reikia tik jūsų API rakto:

```
x-api-key: <YOUR_API_KEY>
```

- **Bazinis URL:** kiekvienas kelias prasideda `https://api.agencyhandy.com/api/v1`. Iškvietus `https://api.agencyhandy.com/accounts/companies` be `/api/v1`, grąžinama `404 API not found`.
- **Antraštė `companyid` (neprivaloma):** senesni pavyzdžiai siunčia `companyid: <YOUR_COMPANY_ID>`. Galite ją toliau siųsti, tačiau tai turi būti paties rakto darbo srities ID. Kitas ID atmetamas su `403 PermissionError`.
- **`Authorization: Bearer <YOUR_API_KEY>`** taip pat veikia, jei jūsų įrankis gali siųsti tik bearer prieigos raktą. Raktą siųskite tik vienoje antraštėje, ne abiejose.
- **`401 Invalid API key (jwt malformed)`** reiškia, kad reikšmė nėra visas raktas: generuodami nukopijuokite visą raktą (API raktų sąraše rodomi tik paskutiniai penki simboliai). **`401 Invalid api token`** reiškia, kad raktas buvo ištrintas.
- Kiekvienas iškvietimas vykdomas su rakto sukūrusio nario teisėmis.

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/members" \
  --header "x-api-key: <YOUR_API_KEY>"
```

Turėdami API raktą, galite naudoti likusią AgencyHandy API dalį. Tęskite su vienu iš toliau pateiktų galinių taškų vadovų.
