AgencyHandy API ļauj automatizēt potenciālo klientu izveidi, klientu pārvaldību, pasūtījumu atjauninājumus un citas darbības no jebkuras ārējās sistēmas vai skripta. Katrs pieprasījums tiek autentificēts ar API atslēgu, ko izveidojat savas darbvietas iestatījumos. Šī rokasgrāmata palīdzēs izveidot atslēgu un veikt pirmo API izsaukumu.

<Note>
  Lai ģenerētu API atslēgu, jums jābūt **SuperAdmin** vai **Admin** savā AgencyHandy darbvietā.
</Note>

## Bāzes URL

Visi API pieprasījumi tiek veikti uz:

```
https://api.agencyhandy.com/api/v1
```

Aizstājiet `{{URL}}` ar šo bāzes URL visos API dokumentācijas piemēru pieprasījumos.

## 1. darbība: ģenerēt API atslēgu

<Steps>
  <Step title="Atveriet darbvietas konfigurāciju">
    Dodieties uz saviem darbvietas iestatījumiem:

    ```
    {{workspaceUrl}}/workspace-config?tab=api-key
    ```

    Tas atver cilni **API Key** darbvietas konfigurācijā.
  </Step>

  <Step title="Ģenerējiet un nokopējiet API atslēgu">
    Noklikšķiniet uz **Generate** (vai **Regenerate**, ja atslēga jau pastāv). Nokopējiet API atslēgu un glabājiet to drošā vietā — izturieties pret to kā pret paroli. AgencyHandy to vairs nerādīs pēc lapas atstāšanas.
  </Step>
</Steps>

<Warning>
  API atslēgas reģenerēšana nekavējoties padara iepriekšējo atslēgu nederīgu. Esošās integrācijas, kas izmanto veco atslēgu, pārstās darboties, līdz tās atjaunināsiet ar jauno atslēgu.
</Warning>

## 2. solis: veiciet pirmo izsaukumu

Nosūtiet savu API atslēgu galvenē `x-api-key`. Atslēga pieder vienai darbvietai, tāpēc API nolasa darbvietu no atslēgas un jums nav jānosūta uzņēmuma ID. Šis izsaukums atgriež atslēgas darbvietas ID un ar to saistītās darbvietas:

### Galapunkts

```
GET {{URL}}/accounts/companies
```

### Galvenes

| Galvene | Vērtība |
|---|---|
| `x-api-key` | Jūsu API atslēga |

### Piemēra pieprasījums

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/accounts/companies" \
  --header "x-api-key: <YOUR_API_KEY>"
```

### Piemēra atbilde

```json
{
  "message": "Companies accosiated with API token.",
  "companyId": "6525994184e9ddd79853450e",
  "companies": [
    {
      "_id": "6525994184e9ddd79853450e",
      "name": "onethread123",
      "logo": "",
      "extraSmallLogo": "",
      "largeLogo": ""
    }
  ]
}
```

`companyId` ir darbvieta, kurai pieder jūsu API atslēga. `companies` uzskaita arī saistītās vecākdarbvietas vai apakšdarbvietas; API atslēga darbojas tikai savai darbvietai, tāpēc izveidojiet atsevišķu atslēgu katrā darbvietā, ko vēlaties automatizēt.

## Autentifikācijas kopsavilkums

Katram autentificētam pieprasījumam nepieciešama tikai jūsu API atslēga:

```
x-api-key: <YOUR_API_KEY>
```

- **Bāzes URL:** katrs ceļš sākas ar `https://api.agencyhandy.com/api/v1`. Izsaucot `https://api.agencyhandy.com/accounts/companies` bez `/api/v1`, tiek atgriezts `404 API not found`.
- **Galvene `companyid` (neobligāta):** vecāki piemēri sūta `companyid: <YOUR_COMPANY_ID>`. Varat to turpināt sūtīt, taču tam jābūt pašas atslēgas darbvietas ID. Cits ID tiek noraidīts ar `403 PermissionError`.
- **`Authorization: Bearer <YOUR_API_KEY>`** darbojas arī tad, ja jūsu rīks var nosūtīt tikai bearer pilnvaru. Sūtiet atslēgu tikai vienā galvenē, nevis abās.
- **`401 Invalid API key (jwt malformed)`** nozīmē, ka vērtība nav pilnā atslēga: kopējiet visu atslēgu, kad to izveidojat (API atslēgu saraksts rāda tikai pēdējās piecas rakstzīmes). **`401 Invalid api token`** nozīmē, ka atslēga ir izdzēsta.
- Katrs izsaukums tiek izpildīts ar tā dalībnieka atļaujām, kurš izveidoja atslēgu.

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/members" \
  --header "x-api-key: <YOUR_API_KEY>"
```

Ar savu API atslēgu varat izmantot pārējo AgencyHandy API. Turpiniet ar kādu no tālāk norādītajām galapunktu rokasgrāmatām.
