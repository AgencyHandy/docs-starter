Met de AgencyHandy API kun je het aanmaken van leads, klantbeheer, orderupdates en meer automatiseren vanuit elk extern systeem of script. Elk verzoek wordt geauthenticeerd met een API-sleutel die je genereert in de instellingen van je workspace. Deze gids leidt je door het genereren van je sleutel en het doen van je eerste API-aanroep.

<Note>
  U moet **SuperAdmin** of **Admin** zijn in uw AgencyHandy-werkruimte om een API-sleutel te genereren.
</Note>

## Basis-URL

Alle API-verzoeken worden gedaan naar:

```
https://api.agencyhandy.com/api/v1
```

Vervang `{{URL}}` door deze basis-URL in alle voorbeeldverzoeken in de API-documentatie.

## Stap 1: Genereer een API-sleutel

<Steps>
  <Step title="Open Werkruimteconfiguratie">
    Navigeer naar uw werkruimte-instellingen via:

    ```
    {{workspaceUrl}}/workspace-config?tab=api-key
    ```

    Dit opent het tabblad **API-sleutel** in Werkruimteconfiguratie.
  </Step>

  <Step title="Genereer en kopieer uw API-sleutel">
    Klik op **Genereren** (of **Opnieuw genereren** als er al een sleutel bestaat). Kopieer de API-sleutel en bewaar deze veilig — behandel deze als een wachtwoord. AgencyHandy toont de sleutel niet opnieuw nadat u de pagina verlaat.
  </Step>
</Steps>

<Warning>
  Het opnieuw genereren van uw API-sleutel maakt de vorige sleutel onmiddellijk ongeldig. Bestaande integraties die de oude sleutel gebruiken, werken niet meer totdat u ze bijwerkt met de nieuwe sleutel.
</Warning>

## Stap 2: Doe je eerste aanroep

Stuur je API-sleutel mee in de `x-api-key`-header. De sleutel hoort bij één workspace, dus de API leest de workspace uit de sleutel en je hoeft geen bedrijfs-ID mee te sturen. Deze aanroep geeft de workspace-ID van de sleutel terug en de workspaces die eraan gekoppeld zijn:

### Eindpunt

```
GET {{URL}}/accounts/companies
```

### Headers

| Header | Waarde |
|---|---|
| `x-api-key` | Uw API-sleutel |

### Voorbeeldverzoek

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/accounts/companies" \
  --header "x-api-key: <YOUR_API_KEY>"
```

### Voorbeeldantwoord

```json
{
  "message": "Companies accosiated with API token.",
  "companyId": "6525994184e9ddd79853450e",
  "companies": [
    {
      "_id": "6525994184e9ddd79853450e",
      "name": "onethread123",
      "logo": "",
      "extraSmallLogo": "",
      "largeLogo": ""
    }
  ]
}
```

`companyId` is de workspace waartoe je API-sleutel behoort. `companies` toont ook alle bovenliggende of onderliggende workspaces die eraan gekoppeld zijn; een API-sleutel werkt alleen voor zijn eigen workspace, dus maak een aparte sleutel aan in elke workspace die je wilt automatiseren.

## Samenvatting authenticatie

Elk geauthenticeerd verzoek heeft alleen je API-sleutel nodig:

```
x-api-key: <YOUR_API_KEY>
```

- **Basis-URL:** elk pad begint met `https://api.agencyhandy.com/api/v1`. Een aanroep naar `https://api.agencyhandy.com/accounts/companies` zonder `/api/v1` geeft `404 API not found` terug.
- **`companyid`-header (optioneel):** oudere voorbeelden sturen `companyid: <YOUR_COMPANY_ID>` mee. Je kunt dit blijven doen, maar het moet de eigen workspace-ID van de sleutel zijn. Een andere ID wordt geweigerd met `403 PermissionError`.
- **`Authorization: Bearer <YOUR_API_KEY>`** werkt ook als je tool alleen een bearer-token kan versturen. Stuur de sleutel in één header, niet in beide.
- **`401 Invalid API key (jwt malformed)`** betekent dat de waarde niet de volledige sleutel is: kopieer de hele sleutel wanneer je hem genereert (de lijst met API-sleutels toont alleen de laatste vijf tekens). **`401 Invalid api token`** betekent dat de sleutel is verwijderd.
- Elke aanroep wordt uitgevoerd met de rechten van het lid dat de sleutel heeft aangemaakt.

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/members" \
  --header "x-api-key: <YOUR_API_KEY>"
```

Met je API-sleutel kun je de rest van de AgencyHandy API gebruiken. Ga verder met een van de onderstaande endpointgidsen.
