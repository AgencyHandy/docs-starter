API AgencyHandy pozwala automatyzować tworzenie leadów, zarządzanie klientami, aktualizacje zamówień i wiele więcej z dowolnego zewnętrznego systemu lub skryptu. Każde żądanie jest uwierzytelniane kluczem API, który generujesz w ustawieniach swojego obszaru roboczego. Ten przewodnik przeprowadzi Cię przez wygenerowanie klucza i wykonanie pierwszego wywołania API.

<Note>
  Aby wygenerować klucz API, musisz być **SuperAdminem** lub **Adminem** w swojej przestrzeni roboczej AgencyHandy.
</Note>

## Bazowy adres URL

Wszystkie żądania API są kierowane na adres:

```
https://api.agencyhandy.com/api/v1
```

Zastąp `{{URL}}` tym bazowym adresem URL we wszystkich przykładowych żądaniach w dokumentacji API.

## Krok 1: Wygeneruj klucz API

<Steps>
  <Step title="Otwórz konfigurację przestrzeni roboczej">
    Przejdź do ustawień przestrzeni roboczej pod adresem:

    ```
    {{workspaceUrl}}/workspace-config?tab=api-key
    ```

    Otworzy się zakładka **Klucz API** w konfiguracji przestrzeni roboczej.
  </Step>

  <Step title="Wygeneruj i skopiuj klucz API">
    Kliknij **Generuj** (lub **Wygeneruj ponownie**, jeśli klucz już istnieje). Skopiuj klucz API i przechowuj go bezpiecznie — traktuj go jak hasło. AgencyHandy nie wyświetli go ponownie po opuszczeniu strony.
  </Step>
</Steps>

<Warning>
  Ponowne wygenerowanie klucza API natychmiast unieważnia poprzedni klucz. Wszelkie istniejące integracje używające starego klucza przestaną działać, dopóki nie zaktualizujesz ich nowym kluczem.
</Warning>

## Krok 2: Wykonaj pierwsze wywołanie

Wyślij swój klucz API w nagłówku `x-api-key`. Klucz należy do jednego obszaru roboczego, więc API odczytuje obszar roboczy z klucza i nie musisz wysyłać identyfikatora firmy. To wywołanie zwraca identyfikator obszaru roboczego klucza oraz powiązane z nim obszary robocze:

### Punkt końcowy

```
GET {{URL}}/accounts/companies
```

### Nagłówki

| Nagłówek | Wartość |
|---|---|
| `x-api-key` | Twój klucz API |

### Przykładowe żądanie

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/accounts/companies" \
  --header "x-api-key: <YOUR_API_KEY>"
```

### Przykładowa odpowiedź

```json
{
  "message": "Companies accosiated with API token.",
  "companyId": "6525994184e9ddd79853450e",
  "companies": [
    {
      "_id": "6525994184e9ddd79853450e",
      "name": "onethread123",
      "logo": "",
      "extraSmallLogo": "",
      "largeLogo": ""
    }
  ]
}
```

`companyId` to obszar roboczy, do którego należy Twój klucz API. `companies` zawiera także powiązane nadrzędne lub podrzędne obszary robocze; klucz API działa tylko dla własnego obszaru roboczego, więc utwórz osobny klucz w każdym obszarze roboczym, który chcesz zautomatyzować.

## Podsumowanie uwierzytelniania

Każde uwierzytelnione żądanie wymaga tylko Twojego klucza API:

```
x-api-key: <YOUR_API_KEY>
```

- **Bazowy URL:** każda ścieżka zaczyna się od `https://api.agencyhandy.com/api/v1`. Wywołanie `https://api.agencyhandy.com/accounts/companies` bez `/api/v1` zwraca `404 API not found`.
- **Nagłówek `companyid` (opcjonalny):** starsze przykłady wysyłają `companyid: <YOUR_COMPANY_ID>`. Możesz nadal go wysyłać, ale musi to być identyfikator własnego obszaru roboczego klucza. Inny identyfikator jest odrzucany z `403 PermissionError`.
- **`Authorization: Bearer <YOUR_API_KEY>`** również działa, jeśli Twoje narzędzie potrafi wysłać tylko token bearer. Wysyłaj klucz tylko w jednym nagłówku, nie w obu.
- **`401 Invalid API key (jwt malformed)`** oznacza, że wartość nie jest pełnym kluczem: skopiuj cały klucz podczas jego generowania (lista kluczy API pokazuje tylko jego ostatnie pięć znaków). **`401 Invalid api token`** oznacza, że klucz został usunięty.
- Każde wywołanie jest wykonywane z uprawnieniami członka, który utworzył klucz.

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/members" \
  --header "x-api-key: <YOUR_API_KEY>"
```

Z kluczem API możesz korzystać z reszty API AgencyHandy. Przejdź do jednego z poniższych przewodników po punktach końcowych.
