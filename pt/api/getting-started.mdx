A API da AgencyHandy permite automatizar a criação de leads, a gestão de clientes, as atualizações de pedidos e muito mais a partir de qualquer sistema externo ou script. Cada pedido é autenticado com uma chave de API que gera nas definições do seu espaço de trabalho. Este guia explica como gerar a sua chave e fazer a sua primeira chamada à API.

<Note>
  Tem de ser **SuperAdmin** ou **Admin** no seu workspace AgencyHandy para gerar uma chave de API.
</Note>

## URL Base

Todos os pedidos à API são feitos para:

```
https://api.agencyhandy.com/api/v1
```

Substitua `{{URL}}` por este URL base em todos os pedidos de exemplo ao longo da documentação da API.

## Passo 1: Gerar uma chave de API

<Steps>
  <Step title="Abrir a Configuração do Workspace">
    Navegue para as definições do seu workspace em:

    ```
    {{workspaceUrl}}/workspace-config?tab=api-key
    ```

    Isto abre o separador **Chave de API** dentro da Configuração do Workspace.
  </Step>

  <Step title="Gerar e copiar a sua chave de API">
    Clique em **Gerar** (ou **Regenerar** se já existir uma chave). Copie a chave de API e guarde-a em segurança — trate-a como uma palavra-passe. O AgencyHandy não a voltará a mostrar depois de sair da página.
  </Step>
</Steps>

<Warning>
  Regenerar a sua chave de API invalida imediatamente a chave anterior. Quaisquer integrações existentes que utilizem a chave antiga deixarão de funcionar até as atualizar com a nova chave.
</Warning>

## Passo 2: Faça a sua primeira chamada

Envie a sua chave de API no cabeçalho `x-api-key`. A chave pertence a um espaço de trabalho, por isso a API obtém o espaço de trabalho a partir da chave e não precisa de enviar um ID de empresa. Esta chamada devolve o ID do espaço de trabalho da chave e os espaços de trabalho associados:

### Endpoint

```
GET {{URL}}/accounts/companies
```

### Cabeçalhos

| Cabeçalho | Valor |
|---|---|
| `x-api-key` | A sua chave de API |

### Exemplo de pedido

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/accounts/companies" \
  --header "x-api-key: <YOUR_API_KEY>"
```

### Exemplo de resposta

```json
{
  "message": "Companies accosiated with API token.",
  "companyId": "6525994184e9ddd79853450e",
  "companies": [
    {
      "_id": "6525994184e9ddd79853450e",
      "name": "onethread123",
      "logo": "",
      "extraSmallLogo": "",
      "largeLogo": ""
    }
  ]
}
```

`companyId` é o espaço de trabalho a que a sua chave de API pertence. `companies` também lista os espaços de trabalho principais ou secundários associados; uma chave de API só funciona para o seu próprio espaço de trabalho, por isso crie uma chave separada em cada espaço de trabalho que pretende automatizar.

## Resumo de autenticação

Cada pedido autenticado só precisa da sua chave de API:

```
x-api-key: <YOUR_API_KEY>
```

- **URL base:** todos os caminhos começam por `https://api.agencyhandy.com/api/v1`. Chamar `https://api.agencyhandy.com/accounts/companies` sem `/api/v1` devolve `404 API not found`.
- **Cabeçalho `companyid` (opcional):** os exemplos antigos enviam `companyid: <YOUR_COMPANY_ID>`. Pode continuar a enviá-lo, mas tem de ser o ID do próprio espaço de trabalho da chave. Um ID diferente é recusado com `403 PermissionError`.
- **`Authorization: Bearer <YOUR_API_KEY>`** também funciona se a sua ferramenta só conseguir enviar um token Bearer. Envie a chave apenas num cabeçalho, não em ambos.
- **`401 Invalid API key (jwt malformed)`** significa que o valor não é a chave completa: copie a chave inteira quando a gerar (a lista de chaves de API só mostra os últimos cinco caracteres). **`401 Invalid api token`** significa que a chave foi eliminada.
- Cada chamada é executada com as permissões do membro que criou a chave.

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/members" \
  --header "x-api-key: <YOUR_API_KEY>"
```

Com a sua chave de API, está pronto para usar o resto da API da AgencyHandy. Continue para um dos guias de endpoints abaixo.
