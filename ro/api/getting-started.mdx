API-ul AgencyHandy îți permite să automatizezi crearea de lead-uri, gestionarea clienților, actualizările comenzilor și multe altele din orice sistem extern sau script. Fiecare cerere este autentificată cu o cheie API pe care o generezi din setările spațiului tău de lucru. Acest ghid te conduce prin generarea cheii și efectuarea primului apel API.

<Note>
  Trebuie să fiți **SuperAdmin** sau **Admin** în spațiul dvs. de lucru AgencyHandy pentru a genera o cheie API.
</Note>

## URL de bază

Toate solicitările API sunt efectuate la:

```
https://api.agencyhandy.com/api/v1
```

Înlocuiți `{{URL}}` cu acest URL de bază în toate solicitările de exemplu din documentația API.

## Pasul 1: Generați o cheie API

<Steps>
  <Step title="Deschideți Configurarea spațiului de lucru">
    Navigați la setările spațiului dvs. de lucru la:

    ```
    {{workspaceUrl}}/workspace-config?tab=api-key
    ```

    Aceasta deschide fila **Cheie API** în interiorul Configurării spațiului de lucru.
  </Step>

  <Step title="Generați și copiați cheia dvs. API">
    Faceți clic pe **Generați** (sau **Regenerați** dacă există deja o cheie). Copiați cheia API și stocați-o în siguranță — tratați-o ca o parolă. AgencyHandy nu o va afișa din nou după ce părăsiți pagina.
  </Step>
</Steps>

<Warning>
  Regenerarea cheii API invalidează imediat cheia anterioară. Orice integrări existente care utilizează cheia veche vor înceta să funcționeze până când le actualizați cu noua cheie.
</Warning>

## Pasul 2: Fă primul apel

Trimite cheia API în antetul `x-api-key`. Cheia aparține unui singur spațiu de lucru, așa că API-ul citește spațiul de lucru din cheie și nu trebuie să trimiți un ID de companie. Acest apel returnează ID-ul spațiului de lucru al cheii și spațiile de lucru asociate acestuia:

### Endpoint

```
GET {{URL}}/accounts/companies
```

### Header-e

| Header | Valoare |
|---|---|
| `x-api-key` | Cheia dvs. API |

### Exemplu de solicitare

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/accounts/companies" \
  --header "x-api-key: <YOUR_API_KEY>"
```

### Exemplu de răspuns

```json
{
  "message": "Companies accosiated with API token.",
  "companyId": "6525994184e9ddd79853450e",
  "companies": [
    {
      "_id": "6525994184e9ddd79853450e",
      "name": "onethread123",
      "logo": "",
      "extraSmallLogo": "",
      "largeLogo": ""
    }
  ]
}
```

`companyId` este spațiul de lucru căruia îi aparține cheia ta API. `companies` listează și eventualele spații de lucru părinte sau secundare asociate; o cheie API funcționează doar pentru propriul spațiu de lucru, deci creează o cheie separată în fiecare spațiu de lucru pe care vrei să-l automatizezi.

## Rezumat autentificare

Fiecare cerere autentificată are nevoie doar de cheia ta API:

```
x-api-key: <YOUR_API_KEY>
```

- **URL de bază:** fiecare cale începe cu `https://api.agencyhandy.com/api/v1`. Apelarea `https://api.agencyhandy.com/accounts/companies` fără `/api/v1` returnează `404 API not found`.
- **Antetul `companyid` (opțional):** exemplele mai vechi trimit `companyid: <YOUR_COMPANY_ID>`. Poți continua să îl trimiți, dar trebuie să fie ID-ul propriului spațiu de lucru al cheii. Un alt ID este refuzat cu `403 PermissionError`.
- **`Authorization: Bearer <YOUR_API_KEY>`** funcționează și dacă instrumentul tău poate trimite doar un token bearer. Trimite cheia într-un singur antet, nu în ambele.
- **`401 Invalid API key (jwt malformed)`** înseamnă că valoarea nu este cheia completă: copiază întreaga cheie când o generezi (lista de chei API afișează doar ultimele cinci caractere). **`401 Invalid api token`** înseamnă că cheia a fost ștearsă.
- Fiecare apel rulează cu permisiunile membrului care a creat cheia.

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/members" \
  --header "x-api-key: <YOUR_API_KEY>"
```

Cu cheia ta API ești gata să folosești restul API-ului AgencyHandy. Continuă cu unul dintre ghidurile de endpoint-uri de mai jos.
