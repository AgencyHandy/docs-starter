API AgencyHandy позволяет автоматизировать создание лидов, управление клиентами, обновление заказов и многое другое из любой внешней системы или скрипта. Каждый запрос аутентифицируется ключом API, который вы создаёте в настройках рабочего пространства. Это руководство проведёт вас через создание ключа и выполнение первого вызова API.

<Note>
  Для генерации API-ключа необходимо иметь роль **SuperAdmin** или **Admin** в вашем рабочем пространстве AgencyHandy.
</Note>

## Базовый URL

Все API-запросы выполняются по адресу:

```
https://api.agencyhandy.com/api/v1
```

Замените `{{URL}}` этим базовым URL во всех примерах запросов в документации по API.

## Шаг 1: Сгенерируйте API-ключ

<Steps>
  <Step title="Откройте настройки рабочего пространства">
    Перейдите в настройки рабочего пространства по адресу:

    ```
    {{workspaceUrl}}/workspace-config?tab=api-key
    ```

    Откроется вкладка **API-ключ** в разделе «Настройки рабочего пространства».
  </Step>

  <Step title="Сгенерируйте и скопируйте API-ключ">
    Нажмите **Сгенерировать** (или **Перегенерировать**, если ключ уже существует). Скопируйте API-ключ и сохраните его в надёжном месте — обращайтесь с ним как с паролем. AgencyHandy не покажет его повторно после того, как вы покинете страницу.
  </Step>
</Steps>

<Warning>
  Перегенерация API-ключа немедленно аннулирует предыдущий ключ. Все существующие интеграции, использующие старый ключ, перестанут работать до тех пор, пока вы не обновите их с новым ключом.
</Warning>

## Шаг 2: Выполните первый вызов

Передайте ключ API в заголовке `x-api-key`. Ключ принадлежит одному рабочему пространству, поэтому API определяет пространство по ключу, и отправлять идентификатор компании не нужно. Этот вызов возвращает идентификатор рабочего пространства ключа и связанные с ним рабочие пространства:

### Конечная точка

```
GET {{URL}}/accounts/companies
```

### Заголовки

| Заголовок | Значение |
|---|---|
| `x-api-key` | Ваш API-ключ |

### Пример запроса

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/accounts/companies" \
  --header "x-api-key: <YOUR_API_KEY>"
```

### Пример ответа

```json
{
  "message": "Companies accosiated with API token.",
  "companyId": "6525994184e9ddd79853450e",
  "companies": [
    {
      "_id": "6525994184e9ddd79853450e",
      "name": "onethread123",
      "logo": "",
      "extraSmallLogo": "",
      "largeLogo": ""
    }
  ]
}
```

`companyId` — это рабочее пространство, которому принадлежит ваш ключ API. `companies` также перечисляет связанные родительские или дочерние рабочие пространства; ключ API работает только для своего рабочего пространства, поэтому создайте отдельный ключ в каждом рабочем пространстве, которое хотите автоматизировать.

## Сводка по аутентификации

Для каждого аутентифицированного запроса нужен только ваш ключ API:

```
x-api-key: <YOUR_API_KEY>
```

- **Базовый URL:** каждый путь начинается с `https://api.agencyhandy.com/api/v1`. Вызов `https://api.agencyhandy.com/accounts/companies` без `/api/v1` возвращает `404 API not found`.
- **Заголовок `companyid` (необязательный):** в старых примерах отправляется `companyid: <YOUR_COMPANY_ID>`. Вы можете продолжать его отправлять, но это должен быть идентификатор рабочего пространства самого ключа. Другой идентификатор отклоняется с ошибкой `403 PermissionError`.
- **`Authorization: Bearer <YOUR_API_KEY>`** тоже работает, если ваш инструмент может отправлять только bearer-токен. Передавайте ключ только в одном заголовке, а не в обоих.
- **`401 Invalid API key (jwt malformed)`** означает, что значение не является полным ключом: скопируйте ключ целиком при его создании (в списке ключей API отображаются только последние пять символов). **`401 Invalid api token`** означает, что ключ был удалён.
- Каждый вызов выполняется с правами участника, создавшего ключ.

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/members" \
  --header "x-api-key: <YOUR_API_KEY>"
```

С вашим ключом API вы готовы использовать остальную часть API AgencyHandy. Перейдите к одному из руководств по конечным точкам ниже.
