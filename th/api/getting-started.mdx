API ของ AgencyHandy ช่วยให้คุณทำงานอัตโนมัติ เช่น การสร้างลีด การจัดการลูกค้า การอัปเดตคำสั่งซื้อ และอื่น ๆ จากระบบภายนอกหรือสคริปต์ใดก็ได้ ทุกคำขอจะยืนยันตัวตนด้วยคีย์ API ที่คุณสร้างจากการตั้งค่าเวิร์กสเปซ คู่มือนี้จะพาคุณสร้างคีย์และทำการเรียก API ครั้งแรก

<Note>
  คุณต้องเป็น **SuperAdmin** หรือ **Admin** บน AgencyHandy workspace ของคุณเพื่อสร้าง API key
</Note>

## Base URL

คำขอ API ทั้งหมดส่งไปยัง:

```
https://api.agencyhandy.com/api/v1
```

แทนที่ `{{URL}}` ด้วย base URL นี้ในคำขอตัวอย่างทั้งหมดตลอดเอกสาร API

## ขั้นตอนที่ 1: สร้าง API key

<Steps>
  <Step title="เปิด Workspace Configuration">
    ไปที่การตั้งค่า workspace ของคุณที่:

    ```
    {{workspaceUrl}}/workspace-config?tab=api-key
    ```

    ซึ่งจะเปิดแท็บ **API Key** ภายใน Workspace Configuration
  </Step>

  <Step title="สร้างและคัดลอก API key ของคุณ">
    คลิก **Generate** (หรือ **Regenerate** หาก key มีอยู่แล้ว) คัดลอก API key และเก็บไว้อย่างปลอดภัย — ปฏิบัติต่อมันเหมือนรหัสผ่าน AgencyHandy จะไม่แสดงอีกครั้งหลังจากคุณออกจากหน้า
  </Step>
</Steps>

<Warning>
  การสร้าง API key ใหม่จะทำให้ key เดิมหมดความถูกต้องทันที การผสานรวมที่มีอยู่ทั้งหมดที่ใช้ key เก่าจะหยุดทำงานจนกว่าคุณจะอัปเดตด้วย key ใหม่
</Warning>

## ขั้นตอนที่ 2: ทำการเรียกครั้งแรก

ส่งคีย์ API ของคุณในเฮดเดอร์ `x-api-key` คีย์เป็นของเวิร์กสเปซเดียว API จึงอ่านเวิร์กสเปซจากคีย์ และคุณไม่จำเป็นต้องส่งรหัสบริษัท การเรียกนี้จะส่งคืนรหัสเวิร์กสเปซของคีย์และเวิร์กสเปซที่เชื่อมโยงกับคีย์นั้น:

### Endpoint

```
GET {{URL}}/accounts/companies
```

### Headers

| Header | Value |
|---|---|
| `x-api-key` | API key ของคุณ |

### ตัวอย่างคำขอ

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/accounts/companies" \
  --header "x-api-key: <YOUR_API_KEY>"
```

### ตัวอย่างการตอบสนอง

```json
{
  "message": "Companies accosiated with API token.",
  "companyId": "6525994184e9ddd79853450e",
  "companies": [
    {
      "_id": "6525994184e9ddd79853450e",
      "name": "onethread123",
      "logo": "",
      "extraSmallLogo": "",
      "largeLogo": ""
    }
  ]
}
```

`companyId` คือเวิร์กสเปซที่คีย์ API ของคุณเป็นเจ้าของ `companies` ยังแสดงรายการเวิร์กสเปซหลักหรือเวิร์กสเปซย่อยที่เชื่อมโยงอยู่ คีย์ API ใช้ได้กับเวิร์กสเปซของตัวเองเท่านั้น ดังนั้นให้สร้างคีย์แยกในแต่ละเวิร์กสเปซที่คุณต้องการทำให้เป็นอัตโนมัติ

## สรุปการยืนยันตัวตน

ทุกคำขอที่ยืนยันตัวตนต้องใช้เพียงคีย์ API ของคุณ:

```
x-api-key: <YOUR_API_KEY>
```

- **Base URL:** ทุกเส้นทางขึ้นต้นด้วย `https://api.agencyhandy.com/api/v1` การเรียก `https://api.agencyhandy.com/accounts/companies` โดยไม่มี `/api/v1` จะส่งคืน `404 API not found`
- **เฮดเดอร์ `companyid` (ไม่บังคับ):** ตัวอย่างรุ่นเก่าส่ง `companyid: <YOUR_COMPANY_ID>` คุณยังส่งต่อไปได้ แต่ต้องเป็นรหัสเวิร์กสเปซของคีย์เอง รหัสอื่นจะถูกปฏิเสธด้วย `403 PermissionError`
- **`Authorization: Bearer <YOUR_API_KEY>`** ก็ใช้ได้เช่นกัน หากเครื่องมือของคุณส่งได้เฉพาะโทเค็น bearer ให้ส่งคีย์ในเฮดเดอร์เดียวเท่านั้น ไม่ใช่ทั้งสอง
- **`401 Invalid API key (jwt malformed)`** หมายความว่าค่าที่ส่งไม่ใช่คีย์ฉบับเต็ม: ให้คัดลอกคีย์ทั้งหมดตอนที่สร้าง (รายการคีย์ API แสดงเพียงห้าตัวอักษรสุดท้าย) **`401 Invalid api token`** หมายความว่าคีย์ถูกลบแล้ว
- ทุกการเรียกทำงานด้วยสิทธิ์ของสมาชิกที่สร้างคีย์

```bash cURL
curl --request GET "https://api.agencyhandy.com/api/v1/members" \
  --header "x-api-key: <YOUR_API_KEY>"
```

เมื่อมีคีย์ API แล้ว คุณก็พร้อมใช้งาน API ส่วนที่เหลือของ AgencyHandy ไปต่อที่คู่มือเอนด์พอยต์ด้านล่างได้เลย
